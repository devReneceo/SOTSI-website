# Site search — how it works & how to take it to Webflow

## Static site (live now, GitHub Pages)
Whole-site search over **~20 pages + 195 blog posts + 181 Deepcast episodes**.

- **Index**: `assets/data/search-index.json` — generated by `tools/build_search_index.py`
  (reuses `blog-index.json` + `episodes-index.json` + parses each page's `<title>`/meta).
  **Re-run `python3 tools/build_search_index.py` whenever blog/podcast data changes.**
- **Engine**: [Fuse.js](https://fusejs.io) v7, self-hosted at `assets/vendor/fuse.min.js` (no CDN).
- **Results page**: `search/index.html` + `search/search.js` + `search/search.css`
  (reads `?q=`, type filters, live search, `<mark>` highlighting, URL-as-state).
- **Entry point**: the footer "Find anything" box on every page is a plain GET form
  (`action="…/search/" method="get"`, depth-aware `../` prefix) → works with **zero JS**.
- URLs in the index are root-relative (no leading slash); the results page prepends a base
  read from `data-base="../"` on `[data-search-results]`, so the subpath deploy resolves correctly.

## Taking it to Webflow (not built yet — two options)

### Option A — Webflow native Search (recommended)
Webflow ships a built-in **Search** element + auto-generated `/search` results page that indexes
all published pages **and** CMS collections (Blog Posts, Courses). Drop the Search input into the
footer symbol; at the Webflow domain root, routing "just works" — zero custom index, auto-maintained.
Limitation: it only indexes content that exists **in the Webflow project** (today: a few curated CMS
items), so full 195/181 coverage grows as that content migrates to the CMS.

### Option B — port this Fuse module (full-corpus parity now)
Serve `search-index.json` + `fuse.min.js` + `search.js` via the existing **jsDelivr-pinned-to-SHA**
mechanism used by `webflow-template/`. Add a Webflow `/search` page with an Embed (results container
carrying `data-search-base="/"` and `data-index="/…/search-index.json"`) + a custom-code `<script>`;
wire the footer symbol's input to route to `/search?q=`. Because `search.js` already reads the base
from data-attrs, it's a near drop-in. Requires the surgical repin after each deploy.

**Recommendation:** enable native search (A) for pages + CMS; keep the Fuse module (B) as the drop-in
for full blog/episode coverage until that content lives in the Webflow CMS.
