SOTSI Website Editing Guide

How to edit seatofthesoul.com in Webflow — safely

Prepared by 22D Marketing · Version 1.0 · 2026-08-17 · Questions: dev@o2s1.com

Read this first

This guide shows you how to edit every section of every page of the SOTSI website yourself — and exactly which parts to leave alone. You don’t need any Webflow experience: every element in the site has been labelled for you.

✎
Editable

Yours to edit — text, photos, links. Double-click text on the canvas to edit it.

⚙
Automatic

Filled automatically on the live site (by code or by the CMS). It may look empty or grey in the Designer — that is normal. ⚙ CMS items are edited in the CMS panel, not on the page.

🔒
Locked

Never edit, delete, or un-hide. 🔒 CODE = the site’s wiring. 🔒 BOARD = blog content that lives in the 22D board. 🔒 SENSOR = hidden blocks other parts of the site depend on.

The fastest safe edit: open any live page, add ?update to the address, change the text, hit Publish. That’s it — recipe #1 below walks you through it.

How this site works

The site has three layers. Knowing which layer something belongs to tells you where to edit it:

  1. Page content in Webflow — headlines, paragraphs, photos, buttons. Edit on the canvas or in Edit mode. Labelled ✎.
  2. Content that lives elsewhere — blog posts (22D board), Deepcast episodes (YouTube sync), the search index, Instagram reels. These flow into the site automatically. Labelled ⚙ or 🔒 BOARD.
  3. The wiring — grey code blocks and hidden sensors that power animations, directories and forms. Labelled 🔒 CODE / 🔒 SENSOR. Never touch.

Why the Designer looks different from the live site

Nothing is broken. This site’s animations, videos and directories are powered by code that only runs on the published site. The Designer canvas (and its Preview mode) can’t run that code — so those areas appear stacked, grey or empty, with dashed “AUTO” notes we added to explain each one. The published site is always the source of truth: after any edit, Publish and check it live.

Webflow basics for this site

Edit mode — the safe door

Add ?update to any live page address. You get the real page with content-only editing: text, images, links, CMS items — no way to break layout. Recommended for everyday text changes.

The Designer

The full app. Left side: Pages panel (choose a page) and Navigator (press Z — the labelled tree of everything). Right side: Settings (D) for links, images and attributes. Double-click text to edit it.

Shared buttons

Buttons marked “(edit in Properties)” are one component reused everywhere. Click once → a small Properties panel appears with Label and Link. Edit there — don’t dig inside.

The CMS

Database icon (F). Books and Courses are edited here as simple forms. Blog and Deepcast collections carry ⚠ warnings — their content is managed outside Webflow.

Publish

Top-right button. Nothing is live until you publish. Then verify on the live site in a normal tab (hard-refresh: Cmd/Ctrl+Shift+R).

Undo & Backups

Cmd/Ctrl+Z for slips. Site settings → Backups to preview & restore whole-site snapshots. Make a manual restore point before a big session: Cmd/Ctrl+Shift+S.

The golden rules

  1. The Designer is not the live site. Animations, videos, the blog directory, episodes, search and Instagram only run on the PUBLISHED site. In the Designer (and in Preview mode) those areas look empty, grey, or stacked — nothing is broken. Always judge the result on the live site.
  2. Follow the labels. Every element in the Navigator is labelled: ✎ = edit freely · ⚙ = automatic (don’t fight it) · 🔒 = never touch. If it has no label or you’re unsure, ask 22D first.
  3. Blog posts live in the 22D board. Write and edit posts in the 22D board, then click “Publish to Website” / “Update on Website”. Editing a post directly in Webflow gets OVERWRITTEN by the next board sync — and a post created only in Webflow never appears in the blog directory.
  4. Never change a published slug. The slug is the last part of the URL. Changing it on a published blog post or episode breaks links and creates duplicates.
  5. Don’t delete or un-hide locked things. Grey 🔒 CODE blocks and hidden 🔒 SENSOR elements are the site’s wiring. Deleting one can silently break a whole page. The eye icon in the Navigator must stay as it is.
  6. Navbar and Footer are shared. They are one component used on every page. Change a link or a button there once — it changes everywhere. That’s usually what you want, but be aware.
  7. Edit content, not structure. Change text, swap photos, update links, edit CMS items. Don’t move sections, don’t rename the small orange class names, don’t restyle. If you want a layout change, ask 22D.
  8. Publish, then verify live. Changes are invisible until you click Publish (top right). After publishing, open the live site in a new tab and check your change. If publishing seems to do nothing, wait a minute and publish again.
  9. Mistake? Undo or restore. Cmd/Ctrl+Z undoes your last steps. For bigger accidents: Site settings → Backups lets you preview and restore an earlier version of the whole site. Nothing is ever truly lost.
  10. When in doubt, ask. A two-minute question to 22D beats a broken page. Email dev@o2s1.com with the page name and what you want to change.

Common tasks — step by step

#1 · Change any text (the safe way)Easy
  1. Open the live page in your browser and add ?update to the end of the address (e.g. …webflow.io/get-started?update). Sign in if asked.
  2. This opens Edit mode — the page looks exactly like the live site, and you can only touch content (no layouts, no styles).
  3. Click the text, type your change.
  4. Click Publish (top right). Open the live page in a normal tab to verify.
#2 · Edit a hero slide (Home)Careful
  1. Open the Designer → Home page. The hero shows all 4 slides stacked, each with an orange “SLIDE N of 4” label.
  2. Double-click the title or text you want to change and type. Keep the gold word inside its gold span (select just the letters, not past the edges).
  3. To change a slide’s photo: click the photo, then in the Settings panel choose Replace Image. Use a large landscape photo (about 1600×900 or bigger).
  4. Publish, then check the live site — let the hero rotate through all 4 slides.
  5. Note: phones and tablets can use a different crop of the same slide photo. If the new photo looks badly framed on a phone, ask 22D to set the mobile crop.
#3 · Replace a photoEasy
  1. Click the photo (it is labelled “✎ … photo/image” in the Navigator).
  2. In the right-hand Settings panel (gear icon, shortcut D), click the image thumbnail → Replace Image → Upload.
  3. Pick a photo with a similar shape (portrait/landscape) and good resolution.
  4. Update the Alt text (a one-line description — it matters for accessibility and Google).
  5. Publish and verify live.
#4 · Change a button’s label or destinationEasy
  1. Click the button once. Buttons labelled “(edit in Properties)” are shared components — a panel appears on the right with a Label field and a Link field.
  2. Edit the Label text and/or the Link, then click out.
  3. Buttons WITHOUT that note are plain links: double-click to edit the text; use the link icon in Settings to change the destination.
  4. Publish and verify live. If the button opens an external site, keep “Open in new tab” checked.
#5 · Edit a book or courseEasy
  1. Open the CMS panel (database icon on the left, shortcut F).
  2. Open the Books or Courses collection and click the item.
  3. Edit the fields (title, description, Buy link…). Field notes tell you what each one does.
  4. Click Save, then Publish the item (green button) — CMS items publish on their own, no full-site publish needed.
  5. Verify on the live /books or /shop page.
#6 · Publish a blog post (22D board)Easy
  1. Blog posts are NOT written in Webflow. Open the 22D board and open (or create) the post in the composer.
  2. Write and Save. Optionally click “Choose cover…” to pick the photo shown on the blog directory.
  3. When the post is approved, click “Publish to Website” (or “Update on Website” for an already-published post) and confirm.
  4. The post appears on the live /blog within a minute. Never change the slug of a post that is already on the site.
#7 · Publish your changesEasy
  1. Click Publish in the Designer’s top-right corner.
  2. Keep the webflow.io domain selected and click Publish to selected domains.
  3. Open the live site in a normal browser tab and verify the change.
  4. If nothing changed, wait a minute and publish again (it occasionally needs a second try).
#8 · Undo a mistake / restore a backupEasy
  1. Small slip: press Cmd+Z (Mac) / Ctrl+Z (Windows) until it’s gone.
  2. Bigger accident: click the Webflow menu (top-left W) → Site settings → Backups.
  3. Hover a backup and use the eye icon to PREVIEW it before restoring.
  4. Click Restore. The site returns to that moment (your newer edits are set aside as another backup). Ask 22D if unsure which backup to pick.

Troubleshooting

A page looks empty, grey, or ‘broken’ in the Designer.

Expected. The dashed AUTO boxes (blog directory, episodes, search, videos, waves) are filled by code on the live site only. See “Why the Designer looks different”.

The Home hero shows all four slides at once.

Only in the Designer — on purpose, so you can edit each slide. The live site rotates them one at a time.

I edited a blog post in Webflow and it reverted.

Blog posts are managed in the 22D board; the next sync overwrites Webflow edits. Make the change in the board and click “Update on Website”.

I changed a stat number and the live site still shows the old one.

Stat numbers animate up to a value stored in a custom attribute (data-count). Edit the visible number AND update data-count in the Settings panel — or ask 22D.

My change doesn’t show on the live site.

Did you click Publish? If yes, hard-refresh the live page (Cmd/Ctrl+Shift+R). If still missing, publish once more — it occasionally needs a second try.

I deleted something by accident.

Cmd/Ctrl+Z immediately. If it’s too late, Site settings → Backups → preview → Restore.

A form, video or feed stopped working after my edit.

You may have touched a 🔒 element. Undo your change and tell 22D what happened — restoring is quick.

Known quirks (not bugs you caused)

  • On phones and tablets, the cookie banner covers the hero slide dots until the visitor accepts or declines it.
  • The video on “In Celebration of Linda Francis” is blocked on the staging domain (Vimeo whitelist) — it will work on the final domain.
  • The Designer’s Preview (eye icon) does not load this site’s effects either — the hero looks stacked/overlapping there. That’s expected; judge on the published site.

Glossary

Designer
Webflow’s full editing app — canvas in the middle, panels on the sides.
Canvas
The page preview you click and edit in the Designer.
Navigator
The tree of every element on the page (press Z). All elements are labelled ✎ / ⚙ / 🔒 for you.
Edit mode (?update)
A safe, content-only editing view of the live site. Add ?update to any page address.
Component
A reusable block (Navbar, Footer, Buttons). Editing the component changes every copy of it.
Properties panel
The small panel that appears when you select a shared Button — edit its Label and Link there.
CMS / Collection
The site’s content database (Books, Courses, Blog Posts…). Items are edited as forms in the CMS panel.
Slug
The last part of a URL (…/blog/kindness → “kindness”). Never change it on published content.
Publish
The button that pushes your saved changes to the live site.
Alt text
A one-line description of an image, read by screen readers and Google.
